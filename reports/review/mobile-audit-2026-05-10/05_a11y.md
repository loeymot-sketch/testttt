## 1. Current mobile A11y audit (ScreenItem single-page)

### 1.1 Interactive `<div>` without keyboard support — multiple P0 (WCAG 2.1.1, 4.1.2)
- `screens-main.jsx:352` meat card: `<div onClick={() => toggleMeat(m.id)}>` — no `role`, no `tabindex`, no `onKeyDown`. Cannot be focused, cannot be activated via keyboard, not announced as a control by AT.
- `screens-main.jsx:379` sauce card: same pattern.
- `screens-main.jsx:403` crudités card: same pattern.
- `screens-main.jsx:425` supplément row (`lc-toggle-row`): same pattern. The visible `lc-checkbox` glyph is a `<div>` with no `role="checkbox"`/`aria-checked`.
- `screens-main.jsx:451` formule menu card: same pattern.
- `shared.jsx:38` TabBar item: `<div ... onClick={() => onChange(t.id)}>` — global navigation NOT keyboard-reachable.

Mirror kiosk: `KioskStepViandeComponent.vue:35-42` (role=group, tabindex=0, @keydown.enter/space), `KioskStepSauceComponent.vue:30-38` (role=checkbox, aria-checked), `KioskStepMenuComponent.vue:24-30` (role=radio inside role=radiogroup).

### 1.2 Toggles not announced as form controls — P0 (WCAG 4.1.2)
- Meat card (`screens-main.jsx:352-360`): visually a multi-select with cap. Should be `role="checkbox"` or, since cap=N enforces FIFO eviction, `role="checkbox"` with `aria-checked` per item plus a counter announcement (kiosk uses `role=group` + visual counter — acceptable bis).
- Sauce card (`screens-main.jsx:379`): multi-select with one-free pricing. Must be `role="checkbox"` + `aria-checked` (kiosk pattern verbatim).
- Crudité card (`screens-main.jsx:403`): default-ON toggles — must be `role="checkbox"` + `aria-checked`. Currently the only visual indicator is `✓` vs `✕` glyph — not announced.
- Supplement row (`screens-main.jsx:425-433`): `role="checkbox"` + `aria-checked` on the row (not just the inner box).
- Formule (`screens-main.jsx:451`): single-select — must be `role="radio"` inside `role="radiogroup" aria-labelledby` referencing the H3.

### 1.3 "Sans Sauce" exclusivity not announced — P1
`screens-main.jsx:276-282` — selecting "Sans Sauce" auto-clears other sauces and vice-versa. AT users get no feedback when their previously-checked sauce becomes unchecked. Need `aria-live="polite"` status node ("Sauce remplacée par Sans Sauce") OR make the "Sans Sauce" item a separate `role="radio"` toggling the group mode.

### 1.4 Count badge `0/4` not announced live — P1 (WCAG 4.1.3)
`screens-main.jsx:346` — `<span>{meatIds.length}/{item.viandes}</span>`. No `aria-live`, no `role="status"`. Mirror kiosk `KioskStepViandeComponent.vue:90` (`aria-live="polite"`) and `KioskStepViandeComponent.vue:103` (validation hint with `role=status aria-live=polite`).

### 1.5 Disabled CTA reason — P1 (WCAG 3.3.1)
`screens-main.jsx:478-526` — when invalid, button uses `disabled={!valid}`. Native `disabled` is OK technically, but the button label changes from "Ajouter au panier" to "Choisis 2 viandes" via inner span (L523). Issues:
- No `aria-describedby` linking the CTA to a stable status region; the button label is the only carrier.
- Native `disabled` removes the button from the focus order, so users cannot land on it to hear the reason.
- Recommended: `aria-disabled="true"` (instead of `disabled`) + `aria-describedby="cta-status"` + a separate `<p id="cta-status" role="status" aria-live="polite">` updated with the remaining count.

### 1.6 Color contrast — `+0,50€` orange on orange-soft — P1 (WCAG 1.4.3)
`screens-main.jsx:384` — `color: var(--orange) #FF5A1F` on `background: var(--orange-soft) #FFE6D6`. Contrast ≈ **2.49 : 1**. **Fails AA 4.5:1** for normal text and **fails 3:1** for large text. Same combo also at `screens-main.jsx:428` (`+ 0,50 €` supplement price) and `screens-main.jsx:454` (formule price). Fix: use `--orange-dark #E54A12` on `--orange-soft` (≈ 3.6:1 — passes AA large only) or, safer, use `--ink` on `--orange-soft` (≈ 13:1) and reserve orange for active borders.

### 1.7 Icon-only buttons missing accessible name — P0 (WCAG 4.1.2)
- `shared.jsx:82-88` `IconBtn` renders `<button>{children}</button>` — no `aria-label` prop. All consumers pass only an SVG child. Affected sites:
  - `screens-main.jsx:303` Back arrow → no name (screen reader hears "button").
  - `screens-main.jsx:305` Heart (favorite) → no name.
  - `screens-main.jsx:306` Close (X) → no name.
- `screens-main.jsx:468-470` quantity stepper: bare `<button>` with only `<I.Minus/>` / `<I.Plus/>` SVG, no `aria-label` ("Diminuer la quantité" / "Augmenter la quantité").
- `mobile/icons.jsx:5` — every SVG has no `aria-hidden="true"` and no `<title>`. They inherit label from parent button when present, but here there is no parent label → completely silent for AT.

### 1.8 Touch targets — P1 (WCAG 2.5.5 AAA but iOS HIG ≥ 44×44)
- `IconBtn` default 40×40 (`shared.jsx:84`) — below iOS HIG 44 minimum.
- Quantity stepper buttons 32×32 (`screens-main.jsx:468`, `screens-main.jsx:470`) — well below 44×44.
- Sauce card no fixed min-height (`screens-main.jsx:379`) — depends on inner padding (10px+content) ≈ 34-38px. Risk fail.
- Crudité card padding `12px 8px` (`screens-main.jsx:403`) — likely OK in width (column ~110px) but verify height ≥44.

### 1.9 No focus styles anywhere — P0 (WCAG 2.4.7)
`mobile/styles.css` (read whole file) contains **zero** `:focus`, `:focus-visible`, or `outline` rule. Browser default outline is the only fallback — and many `<div onClick>` patterns won't even take focus. Mirror kiosk `KioskStepSauceComponent.vue:341` comment: "tactile cards are now role=checkbox" → kiosk has explicit focus rings.

### 1.10 Headings hierarchy — P2 (WCAG 1.3.1, 2.4.6)
`screens-main.jsx:331` h1 = item name. Each section uses h3 (L345, 371, 396, 418, 444). h2 missing → not a fail per se but flag (h1→h3 jump). Acceptable if VoiceOver rotor users don't mind.

### 1.11 Decorative emoji not silenced — P2
- `screens-main.jsx:354` `<span>{m.emoji}</span>` — emoji like `🥩` are read by VoiceOver. Wrap with `aria-hidden="true"` since the meat name is already announced.
- Same for `screens-main.jsx:381` (sauce 🌶️), `screens-main.jsx:493` cart-summary 🍽 emoji.

## 2. Multi-page wizard A11y spec

### 2.1 Header
- **Back button**: `<button aria-label="Retour à l'étape précédente" type="button">`. Replace `IconBtn` (a `<button>` already, but add `aria-label` prop). `aria-hidden="true"` on inner SVG.
- **Step counter** "Étape 1 sur 5": separate `<span role="status" aria-live="polite" aria-atomic="true">`. Updates announce on transition. (Kiosk equivalent: `KioskStepMenuComponent.vue:15` + `:155` + `:200` use `role="status"`.)
- **Progress dots**: `<div aria-hidden="true">` since the counter above is the SSOT for AT (current `Dots` in `shared.jsx:110-118` — wrap in `aria-hidden`).

### 2.2 Step body
- **Step heading**: `<h1 tabindex="-1" id="step-heading">` so JS can `.focus()` on transition (WCAG 2.4.3 focus order). Each step has its own h1 (single-page wizard pattern).
- **Radio groups (single-select)** — kiosk pattern verbatim (`KioskStepMenuComponent.vue:20-30`):
  - Container: `role="radiogroup" aria-labelledby="step-heading"` (or `aria-label`).
  - Item: `role="radio" tabindex="0" :aria-checked="..." :aria-label="..."` + `@keydown.enter`/`@keydown.space` activate + `Arrow` keys move selection.
  - Disabled item: `aria-disabled="true" tabindex="-1"`.
- **Checkboxes (multi-select)** — kiosk pattern (`KioskStepSauceComponent.vue:30-38`):
  - Item: `role="checkbox" tabindex="0" :aria-checked="..." :aria-label="..."` + Enter/Space toggle.
- **Default-ON crudités**: prefer `role="checkbox" aria-checked="true|false"` with `aria-label="Salade"` and a hidden status: "(retiré)" appended when off so VoiceOver announces "Salade, case à cocher, non cochée, retiré". Avoid `aria-pressed` here — the underlying control is binary inclusion/exclusion, semantically a checkbox.
- **Quantity stepper**: `<button aria-label="Diminuer la quantité">` / `<button aria-label="Augmenter la quantité">`. The number `<span aria-live="polite" aria-atomic="true">{qty}</span>` (or use `<output>`). 44×44 px min.

### 2.3 Sticky CTA per step
- Use `aria-disabled="true"` (NOT `disabled`) so the button stays focusable.
- `aria-describedby="cta-status"` pointing to a `role="status" aria-live="polite"` paragraph: "Sélectionne 4 viandes pour continuer".
- When valid: status text announces "Prêt — appuyez pour continuer" (debounced).
- Click handler must guard against `aria-disabled === 'true'`.

### 2.4 Modal / bottom-sheet recap
- Container: `role="dialog" aria-modal="true" aria-labelledby="recap-title"`.
- **Focus trap**: on open, move focus to first focusable inside; on close, return focus to the trigger (cart icon).
- **ESC** closes.
- Backdrop click closes (already standard) and announces nothing.

### 2.5 Live composition price
- `<span aria-live="polite" aria-atomic="true">{total} €</span>` — debounce 250ms to avoid spam. Mirror kiosk validation hints.

## 3. Keyboard nav matrix

| Keys | Behavior | Reference |
|------|----------|-----------|
| `Tab` / `Shift+Tab` | Move focus across interactive elements within step | WCAG 2.1.1 |
| `Enter` / `Space` | Activate radio/checkbox/button | `KioskStepViande:41-42`, `KioskStepSauce:37-38` |
| `Arrow ↑↓ / ←→` inside `radiogroup` | Move selection within group | Kiosk: not implemented per-arrow currently — **mobile must add this** to comply with ARIA APG radiogroup pattern |
| `Home` / `End` inside group | Jump first/last (optional, recommended) | ARIA APG |
| `ESC` | Close modal/sheet; on full-screen step, equivalent to `prev()` | New |
| Swipe (touch) | Optional gesture; never sole action path | WCAG 2.5.1 |

Note: kiosk uses Enter/Space only (no arrow nav) — for **single-select radio** groups (formule, menu choice) mobile MUST add arrow-key roving tabindex per ARIA APG. For `role=checkbox` groups (sauces, supplements), Tab is sufficient.

## 4. Focus management on step transition

- **`next()`**: after route/state swap, `requestAnimationFrame(() => stepHeadingRef.current?.focus())`. Heading has `tabindex="-1"` so it's programmatically focusable but not in tab order.
- **`prev()`**: same pattern — focus the new step's heading.
- **Final "Add to cart"**: focus moves to a toast `role="status" aria-live="assertive"` ("Ajouté au panier — voir mon panier") OR navigates to cart screen and focuses the cart screen header.
- **Modal recap close**: focus returns to the trigger button (cart-icon recap toggle).
- **Validation error on next()**: if user taps disabled CTA somehow, focus jumps to the first invalid section heading + announces missing count.

## 6. Mobile-specific A11y (iOS Safari + VoiceOver)

- **`prefers-reduced-motion`**: no media query in `mobile/styles.css`. Add `@media (prefers-reduced-motion: reduce) { .lc-marquee-track { animation: none; } .lc-pulse { animation: none; } *,*:before,*:after{ transition: none !important; animation-duration: 0.01ms !important; } }`.
- **VoiceOver swipe nav**: with current `<div onClick>` patterns, swipe lands on each `<div>` but it's not announced as a control → user hears the visible text but has no idea it's tappable. Fixing §1.1/§1.2 fixes this.
- **TabBar** (`shared.jsx:34-46`): add `role="tablist"` (or `role="navigation" aria-label="Navigation principale"`), each tab `role="tab" aria-selected={isActive}` (if tablist) OR `aria-current="page"` (if nav). Items must be `<button>` not `<div>`. Add labels for Home/Menu/Receipt/User icons (already have visible labels — good — but the SVG must `aria-hidden="true"`).
- **Safe-area insets**: `--ios-safe-top: 68px` is hard-coded in `styles.css:51`. Use `env(safe-area-inset-top)` instead so it adapts to non-Dynamic-Island devices. Same for bottom: `.lc-tabs` uses `padding: 10px 4px 28px` — should use `env(safe-area-inset-bottom)`.
- **Tap delay**: ensure `touch-action: manipulation` on interactive `<button>`s to remove 300ms delay (perf, also a11y for users on slower CPU).

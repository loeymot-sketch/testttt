## 9.1.5 — `kioskMenu` store `UPDATE_ITEM` mutation

**Verdict: RESOLVED**

`resources/js/store/modules/kioskMenu.js:185-228`:

```js
UPDATE_ITEM(state, payload) {
    // ...
    const idx = state.items.findIndex(i => parseInt(i.id) === parseInt(item_id));
    if (idx === -1) return;
    const current = state.items[idx];
    const patch = {};
    if (...hasOwn 'is_available') patch.is_available = !!payload.is_available;
    else if (...hasOwn 'status')  patch.is_available = payload.status !== 0 && payload.status !== 2;
    if (...hasOwn 'unavailable_reason') patch.unavailable_reason = payload.unavailable_reason;
    else if (...hasOwn 'reason')        patch.unavailable_reason = payload.reason;
    if (patch.is_available === true)    patch.unavailable_reason = null;
    state.items[idx] = { ...current, ...patch };
}
```

Immutable-style spread merge; never clobbers unrelated fields (allergens, category, offers). Supports `type='full'` as a cache-bust hint (`state.lastFetchedAt = null`). The items array is flat (categories live separately), so "deep-safe for nested categories" is not a concern here — the mutation never touches `state.categories`.

## Incidental observations (do NOT block merge)

These adjacent issues were noticed while reading the code but are *not* part of the 14 P9.1 findings:

1. **P1 — `/frontend/order` payload still carries client-computed prices.** `kioskCart.js:334-383` (`submitOrder`) ships `subtotal`, `discount`, `total`, and per-line `item_price` / `total_price`. The backend `FrontendOrderService` is expected to recompute via `PricingService` (SSOT), but the payload fields themselves are a vestigial SSOT leak that should be dropped in a later phase to match the invariant "no price computed in frontend payload to `POST /api/frontend/order`". P9.1.6 only required the promo-specific wiring (code, not amount) — which is correct — so this does not degrade the 9.1.6 verdict.

2. **P2 — `KioskPromoCarouselComponent` relies on server-side promos** (good — server-driven per Phase 8.5), but the UI has no cart-side "applicable" indicator beyond the promo-code field. Unrelated to the 14 findings.

3. **P2 — Minor**: `KioskWizardComponent.vue:1158` uses Vue 2 `beforeDestroy` instead of Vue 3 `beforeUnmount`. Works via Vue 3 compat layer but should be migrated. Unrelated.

4. **P2 — Minor**: the per-line total in `kioskCart.submitOrder` is recomputed client-side from `convert_price * quantity + surcharges`. Not a security issue (server recomputes), but a candidate for cleanup alongside point 1.

## 6. Stale-Prune Window

`oss.stale_window_hours` default **8h** (config/oss.php line 30, env override `OSS_STALE_WINDOW_HOURS`). Query line 117 & 239:

```php
->where('order_datetime', '>=', now('UTC')->subHours((int) config('oss.stale_window_hours', 8)));
```

Wave 3c heal pins `now('UTC')` explicitly so the Carbon-bound literal matches the TIMESTAMP column's storage TZ (sentinel `SisterServicesTzAwareV2Test`). The Wave T R5 KDS-T-R5-03 correction (lines 70-85) restored Paris-local bounds for `order_datetime BETWEEN today_start AND today_end` after empirical evidence that MySQL `session_tz='SYSTEM'` (config/database.php `timezone=null`) reinterpreted UTC strings as Paris-local, dropping the last ~2h of every Paris day from the wall.

## 7. wakeLock TV Acquisition

`PreparingAndReadyComponent.vue` lines 145-150 + 197-214:

- `_acquireWakeLock()` called on `mounted()` (line 146).
- `visibilitychange` listener re-acquires when tab returns visible (line 147-150) — addresses **RED challenge "WakeLock under network flap"**: the browser auto-releases on tab hide / OS lock and the re-acquire path re-fires on visibility resume.
- Feature flag `window.foodkingConfig.ossWakeLockEnabled` (default true if absent — `flag === false` early-return only).
- API guard `!('wakeLock' in navigator)` — Safari iOS <16.4 graceful degrade.
- `beforeUnmount` (line 169-174) releases sentinel + drops visibility listener — no leak.

**Limitation noted**: network flap that does NOT trigger `visibilitychange` (e.g., LAN reconnect without tab refocus) does NOT re-fire `_acquireWakeLock`. The acquire only re-fires on visibility events. For a wall TV that never loses focus this is fine; if the screen-saver kicked in mid-flap it would already trigger a visibility event when the user moves the mouse.

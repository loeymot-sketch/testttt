### [P3] Config-vs-doctrine drift: manual POS discounts default ON, but the config comments still say 'OFF for V1 until F1 fixed' (F1 IS now fixed)
- **Where** : `config/pos.php:155-176 (comment block + 'manual_discount_enabled' => env('POS_MANUAL_DISCOUNT_ENABLED', true)) + app/Services/OrderService.php:2877-2888 (stale 'Default OFF for V1' comment)`
- **Verified facts** : VERIFIED both ways. (1) config('pos.manual_discount_enabled') === bool(true) at runtime (no .env override). (2) The original safety reason for keeping it OFF — the F1 discount->VAT split — IS FIXED: ZReportService carries [LOCK_ZREPORT_F1_DISCOUNT_NETTING] orderDiscountRatio() doing proportional post-discount TVA allocation, and ZReportDiscountNettingTest passes 5/5 ('discounted order z tva is netted to post discount base', 'multi rate discount allocates proportionally', 'total tva exactly equals sum of total by tax rate', 'discounted z close signs and chain verifies'). So a discounted order at 10% VAT signs a CORRECT Z. NO fiscal breach.
- **Why it matters** : This is NOT a fiscal P1 (the self-audit disproved that). It is a documentation/config-hygiene drift: the code comments instruct the reader that discounts are OFF-until-F1, while F1 is fixed and the flag defaults ON. A future maintainer reading the stale comment could wrongly believe discounts are disabled, or wrongly re-disable them. The protecting sentinel (ManualDiscountDisabledV1SentinelTest) force-sets the flag false in every test, so it never asserts the production default.
- **Reproduce** : php artisan tinker --execute="var_dump(config('pos.manual_discount_enabled'));" -> bool(true); php artisan test --filter=ZReportDiscountNetting -> 5 passed (F1 fixed)
- **Decision needed** : OWNER CONFIRM INTENT (low-risk): (a) confirm manual POS discounts ON is the intended V1 behaviour; (b) refresh the stale 'Default OFF for V1 until F1' comments in config/pos.php + OrderService.php to reflect that F1 is fixed and discounts are intentionally enabled; (c) optionally add a sentinel asserting the runtime default is true so the doctrine and the code agree. No frozen-zone change required.

## 3. Points forts (avec preuve)

1. **Double audit obligatoire avant CLOSE** : `AUDIT_VERDICT: PASS` (Claude) + `GPT_FINAL_AUDIT_VERDICT: PASS` (GPT) — `run-cycle.md:157`. Tests verts seuls n'ouvrent **jamais** la fermeture. Vraie défense contre l'illusion « CI green = correct ».
2. **Coordination cross-agent codée**, pas seulement écrite : `agent-activity-log.sh start` refuse mécaniquement (exit 2 + flock) le chevauchement de scope, et `post-execute-guard.sh` refuse `VALIDATE` si la diff sort de la réservation. Combo réel, pas un vœu pieux.
3. **Matrice mémoire à 4 stores fermés** (`MEMORY_MATRIX.md`) : règle « pas de 5e store sans gate » ; OpenSpace et claude-mem **explicitement rejetés** avec justifications. Antidote net contre le sprawl mémoire.
4. **Discipline `EXECUTE_DELEGATION:`** observable, gardée par `post-execute-guard.sh` (exit 1 si manquant). L'audit peut **prouver a posteriori** quel canal a écrit chaque ligne de code.
5. **Plafond 5 + HUMAN_GATE** sur la boucle de remédiation (`run-cycle.md:165`, `auto-remediation.mdc`) — empêche les boucles healing infinies décrites dans `CLAUDE.md §8`.

## 4. Faiblesses / trous où un agent peut dériver sans être bloqué

1. **Contradiction PLAN / AUDIT entre routing.md et le reste** :
   - `routing.md:12` : « PLAN | GPT-5.5/xhigh via codex-extension », `routing.md:18` : « AUDIT PRIMARY | GPT-5.5/xhigh via codex-extension », Claude → escalade critique.
   - `global.mdc:26` + `GLOBAL_SYSTEM_PRIMER §1.1` + `run-cycle.md Step 5` : Claude PRIMARY pour PLAN et AUDIT.
   - Aucun script ne tranche. Un agent peut citer l'un ou l'autre selon ce qui l'arrange. **Drift gouvernance majeur**, contraire à `CLAUDE.md §10`.
2. **`PHASE: IN_PROGRESS` non canonique** dans `ACTIVE_CYCLE.md` ligne 8 : run-cycle.md ne reconnaît que `PLAN/EXECUTE/VALIDATE/AUDIT/CLOSED/GATE`. Step 0 item 2 dit « halt si RUNNER_MODE manquant » mais ne valide pas la valeur de `PHASE`. Un cycle peut donc rester « IN_PROGRESS » indéfiniment, hors machine d'état.
3. **Graphiti = facultatif silencieux**. `run-cycle.md Step 0 item 5` : « si MCP non chargé : note 1 ligne, ne pas bloquer ». L'écriture post-AUDIT (`add_memory`) n'a aucun garde-fou : un cycle peut clôturer sans ingérer la décision durable. La règle (§4.2 Primer) « update sous 48 h » n'est ni testée ni rappelée par script.
4. **`post-execute-guard.sh` aveugle si la diff est vide** (ligne 61 : `aucun changement détecté → OK`). Un EXECUTE qui n'écrit que dans `reports/` ou `missions/` passe sans `EXECUTE_DELEGATION:`. Couplé à un agent qui « rédige juste un rapport », c'est une porte de service.
5. **`verify-orchestration-boucle.sh` ne valide pas le tier** ChatGPT (Plus/Pro). Le contrat exige Pro (gpt-5.5-pro xhigh) ; Plus passe le smoke. La distinction qualité/quota n'est pas mécanisée.
6. **Plafond 5 / HUMAN_GATE non enforcé par script** : c'est une instruction prose. Aucun outil ne lit `REMEDIATION_AUDIT_CYCLE` ni ne refuse un 6e tour. Si l'orchestrateur « oublie », rien ne le rattrape.
7. **Cycle Caisse V1 Masterplay** by-passe `run-cycle.md` standard (Step 0 item 0). Toute la discipline `EXECUTE_DELEGATION` / `agent-activity-log` / double audit est rejouée par un autre runner (`run-masterplay.sh`) non audité ici — angle mort de cet audit, mais aussi du système : le contrat de SSOT décrit dans `MEMORY_MATRIX.md` est délégué à un script externe.

## 5. Recommandations prioritaires (TOP 5)

1. **Trancher PLAN et AUDIT primaires** : éditer `routing.md` pour aligner sur `global.mdc` (Claude PLAN/AUDIT) **ou** rendre `routing.md` autoritaire et corriger `global.mdc` + `run-cycle.md Step 5` + `GLOBAL_SYSTEM_PRIMER §1.1` au même endroit. Une seule version. Sinon ouvrir un gate `docs/gates/GATE_ROUTING_*` figeant la décision.
2. **Validateur de `PHASE`** : ajouter dans `verify:boucle` (ou un nouveau `scripts/validate-active-cycle.sh`) un check qui refuse toute valeur hors `{PLAN, EXECUTE, VALIDATE, AUDIT, CLOSED, GATE}`. État courant `IN_PROGRESS` à corriger immédiatement.
3. **Enforcer le plafond 5** : `post-execute-guard.sh` ou un nouveau `audit-guard.sh` doit lire `REMEDIATION_AUDIT_CYCLE` dans le `REPORT_FILE` et exit non-zéro si > 5 sans gate ouvert dans `docs/gates/`.
4. **Combler le trou diff-vide** : `post-execute-guard.sh` doit aussi exiger `EXECUTE_DELEGATION:` quand `missions/{TASK}/output_codex.json` ou `reports/audit/GPT_SELF_AUDIT_*` ont été modifiés, pas seulement le code produit.
5. **Forcer la mise à jour Graphiti post-AUDIT** : sur `AUDIT_VERDICT: PASS`, `after-execute-memory.sh` doit refuser exit 0 si aucune ligne JSONL n'a été ajoutée **et** que le rapport contient un mot-clé décision (`ADR|invariant|gate|rollout`). Sinon la dérive « décision écrite seulement dans le rapport » continuera.

## Findings

### P0 — D-M13 schema gate still blocks full green

`php artisan test` fails only on `Tests\Feature\Sentinels\QueueNumberUniquenessSentinelTest::orders_have_database_unique_guard_for_branch_queue_number`.

Impact: database does not yet prove uniqueness for `(branch_id, queue_number)`. This is the exact D-M13 gate and must not be patched casually because it needs a migration/backfill/rollback decision.

Evidence:
- `reports/validation/massive-system-2026-04-26/10-phpunit-full.log`
- `tests/Feature/Sentinels/QueueNumberUniquenessSentinelTest.php:18`

Decision: keep D-M13 as a human-gated release blocker.

### P0 — Governance is not release-clean

`git status --short | wc -l` reports `605` entries after validation. Many are pre-existing product/test/orchestration changes, plus generated validation outputs.

Impact: CI and another orchestrator cannot yet reproduce a clean release baseline unless the Train A persistence/cleanup plan is completed.

Evidence:
- `.cursor/ACTIVE_CYCLE.md` still contains W10 primary plus Caisse V1 active section.
- `reports/validation/massive-system-2026-04-26/53-git-status-head.log`

Decision: finish Train A governance before declaring V1 ready.

### P1 — OrderQuote HMAC has a known-key fallback

`app/Services/Order/OrderQuoteService.php:473` falls back to `env('APP_KEY', 'foodking-order-quote')` if `config('app.key')` is empty.

Impact: if an environment is misconfigured, quote HMAC protection can degrade to a known secret instead of failing closed.

Required fix: replace fallback with a hard failure, e.g. throw `LogicException('APP_KEY missing for OrderQuote HMAC')`, and add a sentinel for empty APP_KEY behavior.

### P1 — Queue number microtime fallback still exists in four code paths

Detected:
- `app/Services/FrontendOrderService.php:421`
- `app/Services/OrderService.php:498`
- `app/Services/OrderService.php:873`
- `app/Services/OrderService.php:1295`

Impact: on lock timeout, queue numbers can be generated by timestamp modulo logic, which undermines deterministic uniqueness. This belongs inside D-M13, not a casual patch.

### P1 — Route introspection/deploy tooling breaks on missing Senangpay gateway class

`php artisan route:list --path=api` and admin route-list attempts fail with:

`Class "App\Http\PaymentGateways\Gateways\Senangpay" does not exist`

Evidence:
- `app/Providers/RouteServiceProvider.php:116-121` loads files from `app/Http/PaymentGateways/Routes`.
- `app/Http/PaymentGateways/Routes/senangpay.php:4` imports the missing class.
- Only request/form classes exist for Senangpay; no gateway class exists under `app/Http/PaymentGateways/Gateways/`.

Impact: route reflection, route caching, and deployment diagnostics may fail even though the main test suites pass.

### P1 — Kiosk shell exceeds performance budget

`kiosk-shell.js` is `431KB` with budget `350KB`.

Impact: kiosk load performance is above the declared budget. Playwright still passes, so this is a release quality/performance issue, not a functional break.

### P2 — POS order show bypasses BranchScope before service authorization

`app/Http/Controllers/Admin/PosOrderController.php:55` loads an order with `withoutGlobalScope(BranchScope::class)` and delegates to `OrderService::show($order, false)`.

Impact: may be legitimate if the service enforces branch isolation, but this pattern must remain covered by branch isolation tests because controller-level global scope is intentionally bypassed.

### P2 — KDS version model has known Phase 3 debt

`app/Services/KdsSyncService.php:129-133` documents that `status_changed_at` is needed later to avoid missing status-only changes.

Impact: current tests pass; this is a tracked future sync hardening item, not a release blocker if current sentinels remain green.

## Release Decision

`V1_RELEASE_DECISION: BLOCKED`

Minimum unblock sequence:

1. Close governance Train A: persist sentinels, quote subsystem, active cycle/memory policy.
2. Fix/fail-closed OrderQuote APP_KEY HMAC behavior.
3. Resolve missing Senangpay gateway route class or disable/remove route under explicit payment-gateway decision.
4. Complete D-M13 queue number uniqueness with human-signed migration/backfill plan.
5. Re-run `php artisan test`, `npx vitest run`, `npx playwright test`, strict legacy lint, i18n audit, bundle budget.
6. Decide whether i18n and kiosk-shell budget are hard release gates or post-V1 quality gates.

## Audit Honesty

This audit accounted for the whole repository through inventory, full test suites, E2E, route/tooling probes, and static critical-pattern scans. It did not manually read all 4,784 files line by line. The residual risk is therefore represented by the dirty worktree and static findings, not hidden as a false PASS.

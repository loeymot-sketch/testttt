## Implementation

- OTP resend now calls the existing `guestOtp` API with the current phone.
- The resend control starts disabled for 30 seconds, prevents duplicate requests,
  exposes loading state, and shows sanitized French errors for network/429/other failures.
- Local `dev_code` is copied into UI state only when the API explicitly returns it
  and remains gated by `LC.isDev`; stale local state is cleared on a new attempt
  before every resend, on a new login attempt, and on logout. A resend response
  without `dev_code` cannot restore the previous local code.
- `realAuth.js` accepts only loopback `LC_API_BASE` values, consumes the returned
  local `dev_code`, never guesses an OTP, and returns sanitized failures without
  stringifying or logging API JSON, tokens, OTPs, or phone numbers.

### E2E proof

The focused browser flow verified:

1. Login sends exactly one local OTP request.
2. The resend button is disabled during the 30-second cooldown; two forced DOM clicks create no additional request.
3. After expiry, one resend creates exactly one additional OTP request.
4. The returned local `dev_code` is displayed and used for verification.
5. Successful verification reaches the Home screen.

## Explicit blocker

The external SMS provider is not wired in this local environment. `dev_code` is
therefore available only under the existing local-only backend guard. The server
test confirms it is absent in public staging and production, so this change does
not fake production SMS and production readiness still requires provider
configuration plus a real SMS delivery test.

The generic post-execute hook also reported the known unrelated cents regression:
`€1.005` converts to 100 cents while the existing test expects 101. No payment
file was changed because payment is explicitly outside this OTP mission.

The post-execute scope guard found the worktree already contains unrelated
Phase 3, governance, screenshots and Brother-printer changes. It therefore
returned exit 4 for the whole worktree even though the six files listed above
are the only files changed by this Phase 4 execution. Those pre-existing
changes were preserved and not reverted.

The repository-wide `git diff --check` also sees one trailing-whitespace line
in the pre-existing `reports/post_execute_latest.log` generated by the generic
hook; it is outside this mission and was not altered.

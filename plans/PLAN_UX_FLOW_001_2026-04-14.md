## Execution Steps

### Step 1 — KDS: Fix filter reset after status change
**File:** `resources/js/components/admin/kitchenDisplaySystem/KitchenDisplaySystemComponent.vue`
**Bug:** `_debouncedRefresh()` calls `this.list()` with no arguments, which resets `props.search.status` to `""`. After a chef changes an order status (PREPARING → PREPARED), the debounced refresh clears the active filter tab back to "all orders" instead of preserving the current filter.
**Fix:** `_debouncedRefresh()` should call `_refreshWithCurrentFilter()` instead of `list()` to preserve the active status filter. Alternatively, modify `_debouncedRefresh` to pass the current `props.search.status` to `list()`.

### Step 2 — KDS: Add empty state messages for all columns
**File:** `resources/js/components/admin/kitchenDisplaySystem/KitchenDisplaySystemComponent.vue`
**Bug:** Only the kiosk column shows an empty message ("Aucune commande borne en cours"). Dine-in, online, and takeaway columns show nothing when empty.
**Fix:** Add empty state messages for dine-in (`dineinOrders`), online (`onlineOrders`), and takeaway (`takeawayOrders`) columns using the same pattern as kiosk. Use i18n keys if available, otherwise add minimal French text consistent with existing kiosk column copy.

### Step 3 — KDS: Add orderItems to Vuex initial state
**File:** `resources/js/store/modules/kitchenDisplaySystemOrder.js`
**Bug:** `orderItems` is committed and read via getter but not declared in initial `state`, which can break Vue reactivity.
**Fix:** Add `orderItems: []` to the initial state object.

### Step 4 — KDS: Add error handling for failed API loads
**File:** `resources/js/components/admin/kitchenDisplaySystem/KitchenDisplaySystemComponent.vue`
**Bug:** `.catch` blocks only toggle `loading.isActive = false` with no user feedback.
**Fix:** Add `alertService.error()` in catch blocks for `_refreshWithCurrentFilter()` and `items()` failures so the chef sees a toast on network errors.

### Step 5 — OSS: Fix PopularItemComponent missing :key
**File:** `resources/js/components/admin/orderStatusScreen/PopularItemComponent.vue`
**Fix:** Add `:key="item.id"` (or a suitable stable key) to the `v-for` on items.

### Step 6 — OSS: Remove dead computed properties
**File:** `resources/js/components/admin/orderStatusScreen/PreparingAndReadyComponent.vue`
**Bug:** `orders` and `items` computed properties are declared but never used in the template.
**Fix:** Remove the unused computed properties.

### Step 7 — OSS: Add error handling for failed API loads
**File:** `resources/js/components/admin/orderStatusScreen/PreparingAndReadyComponent.vue`
**Fix:** Add `alertService.error()` in the `.catch` block of `list()`.

### Step 8 — Delivery: Fix v-for keys
**Files:** `resources/js/components/admin/deliveryBoys/DeliveryBoyListComponent.vue`, `resources/js/components/admin/deliveryBoys/deliveredOrder/DeliveredOrderList.vue`
**Bug:** `v-for` uses object reference as key (`:key="deliveryBoy"`, `:key="order"`) instead of stable IDs.
**Fix:** Change to `:key="deliveryBoy.id"` and `:key="order.id"` respectively.

### Step 9 — Admin: Fix duplicate id="switcher" in KioskMachineListComponent
**File:** `resources/js/components/admin/settings/KioskMachine/KioskMachineListComponent.vue`
**Bug:** Every row in the `v-for` uses `id="switcher"` on the toggle checkbox — duplicate HTML IDs.
**Fix:** Make IDs unique per row: `id="'switcher-' + machine.id"` (and update corresponding `for` attribute if present).

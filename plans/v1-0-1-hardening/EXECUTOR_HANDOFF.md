## Mode A — Claude Subagent-Driven Development (recommended)

**Skill**: `superpowers:subagent-driven-development`

**Pattern**:
1. Orchestrator (this session) reads MASTER plan §9 sprint-by-sprint
2. For each task, dispatch a fresh sub-agent via `Agent` tool with the task's full step-by-step content from MASTER
3. Each sub-agent: TDD (RED test → minimal implementation → GREEN → commit)
4. Orchestrator reviews each commit before next task
5. Per-sprint smoke: orchestrator runs sprint's PHPUnit filter

**Estimated wall-clock**: ~10-14 days at 2-3 tasks/day pace with reviews.

**Pros**:
- Fresh context per task = no context bloat
- Orchestrator can intervene at any review checkpoint
- Same project memory + frozen-zone discipline across all tasks (orchestrator continuity)

**Cons**:
- Higher token cost (each sub-agent re-loads CLAUDE.md, BRAIN, etc.)
- Slower wall-clock than inline batch

**To start**: User says "start H1 subagent" → orchestrator dispatches H1.1 sub-agent.

## Mode B — Claude Inline Execution

**Skill**: `superpowers:executing-plans`

**Pattern**:
1. Orchestrator (this session) executes tasks directly in main context
2. Per-task TDD discipline preserved (RED test → GREEN → commit)
3. Per-sprint checkpoint: smoke run + review
4. Cross-sprint: orchestrator advances to next sprint after smoke green

**Estimated wall-clock**: ~6-8 days but lower per-task review density.

**Pros**:
- Faster wall-clock (no sub-agent context reload)
- Cheaper token cost
- Direct test-feedback loop

**Cons**:
- Context bloat over 30 tasks (orchestrator may need /compact mid-cycle)
- Less natural review checkpoints

**To start**: User says "start H1 inline" → orchestrator begins H1.1 directly.

## Mode C — Codex/Cursor Handoff

**Skill**: `handoff-cursor`

**Pattern**:
1. Orchestrator generates a Codex-compatible handoff package (one prompt per sprint)
2. User executes in Codex/Cursor session
3. User commits work, returns to Claude for validation
4. Claude validates: file:line check + tests + frozen-zone diff
5. Repeat per sprint

**Estimated wall-clock**: 1 day Claude planning + N days Codex execution + 0.5 day Claude validation per sprint.

**Pros**:
- Frees Claude main session for orchestration / next planning
- Codex/Cursor inline editing UX is strong
- Lower Claude token cost

**Cons**:
- Context handoff overhead per sprint
- Two-tool quality discipline drift risk
- Codex/Cursor may not have access to Wave Z findings reports — must be packaged

**Handoff package per sprint** (auto-generated by `handoff-cursor` skill):
- Sprint sub-plan section (verbatim from MASTER §9)
- File paths to touch (Create / Modify / Test)
- Acceptance criteria
- Rollback instructions
- Commit message template
- Smoke test commands
- Pointer to `OWNER_GATES.md` if relevant
- Pointer to `reports/test-e2e/wave-z-2026-05-16-claudemax/CONVERGENCE_FINAL.md` for context

**To start**: User says "generate H1 handoff for Codex" → orchestrator invokes `handoff-cursor` skill.

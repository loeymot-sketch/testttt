**Data-recording touchpoints:**
  - totalOrders() KPI persists nothing but RECORDS A NUMBER THE OWNER TRUSTS: it counts status=DELIVERED only. On a single-box fast-food where POS cash tickets close PAID and kiosk orders may end at PREPARED/picked-up without a DELIVERED transition, the dashboard 'total orders' card silently undercounts real business volume vs the orders table — owner-visible mis-recording of headline activity (DASH-01).
  - Branch scoping is enforced in PHP (dashboardBranchId()), NOT via global BranchScope, for Order/Customer aggregation; auditTrail() and AuditLog are in BranchScope EXEMPTED_MODELS so the manual where('branch_id') filter is the ONLY guard — a regression here would leak cross-branch fiscal/audit data into a branch manager's dashboard.
  - EOD PDF (eodSynthesis) aggregates CA + TVA + payment-method + channel breakdown for a day and is archivable (NF525 6y retention). Risk: dual-column payment reality (pos_payment_method vs payment_method) — if an order has the wrong order_type/source_surface it lands in the wrong bucket (cash vs card vs ticket-resto vs counter), mis-recording the daily payment-method split the accountant relies on.
  - Paris-day boundary binding (resolveDayBoundaryParis) assumes MySQL session_tz=SYSTEM=Paris. If config/database.php connections.mysql.timezone is ever set to +00:00, every time-windowed KPI (orderStatistics, salesSummary, realtime, channel, eodSynthesis) silently shifts the day window ±2h and drops/duplicates boundary orders — a date-attribution mis-recording.
  - channelStatistics() / bucketChannels() classify revenue into Web vs Kiosk/App vs POS using source_surface='kiosk' as canonical marker. A kiosk order missing source_surface mis-records as Web — the owner's channel-mix analytics (where money comes from) is corrupted without any error.
  - realtimeReport daily_orders counts ALL placed orders incl PENDING_COUNTER (not yet paid) while daily_sales counts PAID — the two cards on the same row use different bases; an owner reading them as a pair can mis-interpret conversion/average.
  - Sidebar reachability is computed, not static: buildMergedSidebarMenus + V1_HIDDEN_MENU_MODULES decide which buttons render. A hidden module's ROUTE still exists (direct-URL reachable) — the data-integrity concern for the owner's 'all buttons lead somewhere' audit is the inverse: a rendered button whose route was renamed/removed would dead-end (none found today; all 25 sidebar + quick-access destinations verified present in the Vue router).

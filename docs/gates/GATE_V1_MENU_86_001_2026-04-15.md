## Decision Required
Approve creation of the `item_branch_availability` table with the following schema:

| Column | Type | Notes |
|---|---|---|
| id | bigint auto | PK |
| item_id | bigint unsigned | FK → items(id) ON DELETE CASCADE |
| branch_id | bigint unsigned | FK → branches(id) ON DELETE CASCADE |
| is_available | boolean | Default true |
| unavailable_reason | varchar(32), nullable | out_of_stock, seasonal, closed_today, manual |
| unavailable_since | datetime, nullable | When the item was marked unavailable |
| max_daily_qty | int unsigned, nullable | null = unlimited |
| daily_consumed_qty | int unsigned | Default 0 |
| daily_reset_at | date | Reset date for daily counter |
| created_at / updated_at | timestamps | Standard |

Indexes:
- `UNIQUE (item_id, branch_id)` — one availability record per item per branch
- `INDEX (branch_id, is_available)` — fast lookup of unavailable items for a branch

Foreign keys: cascading deletes on both `item_id` and `branch_id`.

Estimated storage: ~120 bytes/row. For 200 items × 3 branches = 600 rows = ~72KB. Negligible.

# V4.1 — Wizard unifié POS ↔ Kiosk (à exécuter en session dédiée)

> **Status** : flag feature + wrapper route livrés en V4. **Vraie unification = V4.1**.
> Ce document cadre précisément le périmètre pour la prochaine session.

## Contexte

Actuellement FoodKing a **deux wizards de commande distincts** :

| Surface | Fichier | Lignes | Paradigme |
|---------|---------|--------|-----------|
| POS caisse | `public/js/pos-wizard.js` + `resources/js/components/admin/pos/ItemComponent.vue` | 5763 + 1076 | Vanilla JS qui observe `#item-variation-modal` et intercepte XHR `admin/item/*` |
| Kiosk borne | `resources/js/components/frontend/kiosk/KioskWizardComponent.vue` | 1408 | Vue natif multi-step (stepper) |

**Le user a demandé** : que la borne utilise la **même UX que le POS** — single-page, emojis, counters, crudités pré-sélectionnées, formule, aperçu ticket.

## Options techniques (avec trade-offs)

### Option A — Bridge vers `pos-wizard.js` (pragmatique, découplé)

**Principe** : patcher `pos-wizard.js` pour accepter une source de données externe (pas seulement XHR admin), et faire monter par le Kiosk le même scaffold DOM `#item-variation-modal`.

**Steps** :
1. Ajouter dans `pos-wizard.js` un entrypoint `window.POS_WIZARD_FEED({ itemData, mode: 'kiosk'|'pos', onConfirm })` qui bypass XHR + injecte les données
2. Créer `KioskWizardBridge.vue` qui :
   - Fetch item via `frontend/item/:slug`
   - Render le scaffold `#item-variation-modal` attendu par pos-wizard.js
   - Appelle `window.POS_WIZARD_FEED(...)` avec le payload
   - Écoute le callback `onConfirm(payload)` → dispatch `kioskCart/addItem`
3. Extraire la logique "submit" POS-spécifique de pos-wizard.js dans une fonction pure `buildCartPayload()` appelable en mode kiosk

**Pros** : réutilise 100% de l'UX POS existante, rollback instant via flag.
**Cons** : pos-wizard.js reste vanilla JS ; toucher à 5763 lignes est risqué ; flux commande kiosk coupé au worst case.

**Effort** : 2-3 sessions d'implémentation + tests Playwright complet.

### Option B — Réécriture Vue partagée (propre, long terme)

**Principe** : extraire l'UX wizard dans un composant Vue partagé `<SharedItemWizard>` consommé par POS et Kiosk.

**Steps** :
1. Créer `resources/js/components/shared/item-wizard/` (wizard, viande counter, crudité tags, formule selector, preview ticket)
2. Brancher depuis `admin/pos/ItemComponent.vue` en remplacement progressif de la modale actuelle
3. Brancher depuis `frontend/kiosk/KioskWizardComponent.vue` en remplacement total
4. Déprécier `public/js/pos-wizard.js` (garder jusqu'à parité UX vérifiée)

**Pros** : SSOT UX, maintenance simple, tests Vue faciles.
**Cons** : effort important, risque de régression POS pendant la migration, nécessite un vrai parcours de QA.

**Effort** : 4-6 sessions + plan de migration progressif POS.

## Recommandation

**Option A** pour V4.1 (rapide), **puis** Option B pour V2.0 (propre).
